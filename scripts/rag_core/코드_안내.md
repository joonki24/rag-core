# rag_core 코드 안내 (처음 보는 사람용)

> 2026-10-16 작성. 코드는 바꾸지 않고, 어디서부터 읽으면 되는지만 정리했습니다. 자세한 기준과 결과는 `CHANGES.md`, 설치·실행은 `README.md`에 있습니다. 공유 저장소(rag-core)는 평가 실행에 쓰는 코드만 담았습니다. `tests/`, `CHANGES.md`, 보조 실험용 코드, 실제 문서 파일 이름·지문이 든 정답지 설정(`gold_format_v05·fmtb01·fmtc01·fmtd01.yaml`)은 없습니다. 코드 주석의 "묶음 N"은 원 저장소의 변경 기록 번호입니다.

---

## 1. 이 코드가 하는 일 한 줄

**"엑셀 문서를 어떤 방식으로 카드(청크)로 만들었을 때, 질문에 필요한 근거를 더 잘 찾는가"를 재는 평가 도구**입니다.

- 카드를 만드는 방식이 여러 개 있습니다(기준선 B0-R·B0-S·B0-RC, si-prep이 만든 B1).
- 같은 질문, 같은 검색, 같은 분량(토큰 예산 4,000)으로 카드를 담고, 정답지에 적힌 근거 행을 몇 개 담았는지 셉니다.
- 답을 쓰는 LLM은 평가의 중심이 아닙니다. 보조 평가(답 비교)에서만 씁니다.

## 2. 큰 흐름

```
[엑셀 원본]
   │  b0_chunks.py / b0_recursive.py (기준선 카드)      si-prep(B1 카드)
   ▼
[청크 파일 chunks.jsonl]  ── adapter.py: 읽고 모양 검사 ──▶ [Chroma 서랍(색인)]  ← pipeline/embed_store.py
                                                              │
[정답지 엑셀] ── gold_xlsx_convert.py: 변환 → 사람 확인 ──▶ [정답표 JSON]
                                                              │
                        eval_runner.py (한 번 실행)            ▼
   질문마다:  pipeline/query_engine.search  →  evidence.py (예산까지 담기)
                                             └ B1 검색+연결이면 link_expansion.py (링크 따라 카드 추가)
              → scoring.py (근거 행을 몇 개 담았나 채점)
                                                              ▼
                                              [run_result.json, run_info.json]
                                                              │
                        ../compare_runs.py: 두 실행 비교(95% 구간) ▼
                                              [B1 − 기준선 차이]
```

## 3. 처음 읽을 순서 (이 순서면 전체가 보입니다)

1. **`evidence.py`** (115줄): 가장 짧고 핵심입니다. "검색 순위대로 카드를 담다가 4,000토큰을 넘기 직전에 멈춘다"가 전부입니다.
2. **`scoring.py`의 `score_run`, `compare`**: 담은 카드가 정답 근거 행을 덮었는지 세고, 두 실행의 차이를 부트스트랩으로 비교합니다.
3. **`eval_runner.py`의 `run_evaluation`**: 위 둘을 묶어 한 번 실행하는 함수입니다. 위에서 아래로 읽으면 "정답 읽기 → 청크 읽기 → 색인 확인 → 질문마다 검색·담기 → 채점 → 파일 저장" 순서 그대로입니다.
4. **`link_expansion.py`의 `gather_with_links`**: B1 "검색+연결" 팔만 쓰는 부분입니다. 예산을 검색 몫과 연결 몫으로 나눠 담습니다.
5. **`b0_chunks.py`, `b0_recursive.py`**: 기준선 카드를 만드는 곳입니다.
6. 나머지는 필요할 때만 보면 됩니다(아래 표).

## 4. 파일 지도 (역할별)

### 핵심 (평가 한 번에 꼭 쓰임)
| 파일 | 하는 일 | 먼저 볼 함수 |
| --- | --- | --- |
| `eval_runner.py` | 질문 → 검색 → 담기 → 채점을 한 번에 돌리고 결과 파일을 씀 | `run_evaluation`, `run_questions` |
| `evidence.py` | 검색 순위대로 토큰 예산까지 카드 담기 | `collect_evidence`, `gather` |
| `scoring.py` | 정답표 읽기, 채점, 두 실행 비교 | `score_run`, `compare` |
| `adapter.py` | 청크 파일을 읽고 모양을 검사, 색인에 넣기, 서랍 이름 정하기 | `read_chunks`, `ingest_chunks`, `collection_for` |
| `settings.py` | 설정 yaml을 읽고, 정해 둔 고정값(예산·후보 수 등)을 어기면 멈춤 | `load_settings`, `apply_settings` |
| `pipeline/embed_store.py` | 로컬 임베딩(bge-m3)과 Chroma 서랍 | `embed_texts`, `get_collection` |
| `pipeline/query_engine.py` | 질문과 가까운 카드 찾기 | `search` |
| `config.py` | 경로·모델 이름 같은 공통 값, 외부 API 차단 | — |

### 카드(청크) 만들기
| 파일 | 하는 일 |
| --- | --- |
| `b0_chunks.py` | B0-R(행 하나 = 카드 하나, `열이름: 값`)과 B0-S(같은 줄을 500자씩)를 함께 만듦 |
| `b0_recursive.py` | B0-RC(일반 리커시브: 모든 시트, 열 이름 없이 500자) |

### B1 전용
| 파일 | 하는 일 |
| --- | --- |
| `link_expansion.py` | si-prep 링크를 따라 이웃 카드를 담음(검색+연결 팔) |
| `priority.py` | 요구사항 카드를 먼저 담는 규칙(설정에 있을 때만) |

### 정답지
| 파일 | 하는 일 |
| --- | --- |
| `gold_xlsx_convert.py` (가장 큼, 1,400줄) | 정답지 엑셀 → 정답표 JSON. 데이터마다 양식이 달라 읽는 함수가 여러 개(`*_fmtb01`, `*_fmtc01` 등). 사람이 확인(`confirm`)한 정답표만 평가에 쓰임 |
| `gold_format*.yaml` | 정답지 양식별 설정(열 이름, 문서 파일, 기대 개수) |

### 실행 관리
| 파일 | 하는 일 |
| --- | --- |
| `eval_gate.py` | "동결": 평가 전에 입력·설정·코드 지문을 저장하고, 실행 때 같은지 확인 |

### 불러오기만 하는 것
| 파일 | 하는 일 |
| --- | --- |
| `topic_search.py`, `hybrid_search.py`, `diversity.py` | 예전에 시험한 검색 방식·담기 변형. `eval_runner.py`가 불러오지만 기본 설정에서는 쓰지 않음 |

### 이 저장소에 없는 것
- 시험(`tests/`), 변경 기록(`CHANGES.md`), 가져온 원본 사본(`_origin/`), 보조 실험용 코드(답변 평가, 링크 용도 검증, 보조 지표 등)는 원 저장소에만 있습니다.

## 5. 결과 파일 읽는 법

실행 한 번이 끝나면 출력 폴더에 세 파일이 생깁니다.

| 파일 | 내용 |
| --- | --- |
| `run_result.json` | 질문마다 담은 카드 id, 점수(예: `"3/4"` = 필수 단위 4개 중 3개 찾음), 전체 점수 |
| `run_info.json` | 언제, 어떤 설정·청크·정답표로 돌렸는지(지문 포함), 단계별 걸린 시간 |
| `run_summary.md` | 사람이 읽는 요약 |

## 6. 용어

| 용어 | 뜻 |
| --- | --- |
| 카드 = 청크 | 검색해서 LLM에 넣는 글 한 조각 |
| 팔(arm) | 비교하는 방식 하나. `b0_r`, `b0_s`, `b1_search`(B1 검색만), `b1_link`(B1 검색+연결) |
| 서랍(collection) | Chroma 안에서 방식별로 카드를 나눠 담는 칸. 이름은 `{데이터셋}_{방식}` |
| 토큰 예산 | 질문 하나에 담을 수 있는 카드 글의 총량(4,000토큰, cl100k) |
| 필수 근거 / 단위 | 정답지에 적힌 "이 질문에 답하려면 꼭 필요한 행". 단위 하나에 행이 여러 개일 수 있음 |
| 회수율(점수) | 필수 단위 중 담은 카드가 덮은 비율. 행의 50% 이상을 덮으면 그 단위를 찾은 것으로 셈 |
| 동결 | 결과를 보기 전에 입력·설정·코드를 고정해 두는 것. 결과를 보고 바꾸지 못하게 막음 |
| 사전 등록 | 실행 전에 무엇을 어떻게 잴지 `CHANGES.md`에 적어 두는 것 |
| [사후] | 결과를 본 뒤 한 분석. 참고로만 씀 |
| 95% 구간 | 질문을 다시 뽑아 여러 번 계산했을 때 차이가 나올 범위. 아래 끝이 0보다 커야 "낫다"고 말함 |

## 7. 자주 하는 일

```
# 평가 한 번(개발용). 저장소 밖 파일을 읽을 때는 python -I 권장(README 참고)
python eval_runner.py --arm b0_r --chunks <청크.jsonl> --gold-dir <정답표 폴더> \
       --out <출력 폴더> --purpose dev --chunk-build b0_profile --settings <설정.yaml> --reindex

# 두 실행 비교
python ../compare_runs.py --target <B1 출력 폴더> --base <기준선 출력 폴더> --purpose dev
```
